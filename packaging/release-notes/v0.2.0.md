fastframe 0.2.0 lets apps look like they belong on each platform: text can be drawn with the platform's own interface face (San Francisco, Segoe UI, or the desktop's `system-ui`), and a new crate draws colour emoji in the platform's own style. The tray menu can also change while an app runs. It is 0.2.0 rather than 0.1.8 because two changes can break an app's build; the upgrade section below lists them.

Upgrade by moving the tag on every fastframe crate:

```toml
fastframe-fonts = { git = "https://github.com/crmne/fastframe", tag = "v0.2.0" }
```

## New

- **Text can be drawn with the platform's own interface face.** `FontSetup::default().primary(Primary::System)` draws with San Francisco on macOS (at its text optical size), Segoe UI Variable or the display settings' message font on Windows, and fontconfig's `system-ui` on Linux, so GNOME's Adwaita Sans or a person's own sans-serif choice applies. Every weight comes from the face's `wght` axis or its nearest static face. A face that cannot draw upright Latin is refused and Inter draws instead, and the script fallbacks sit on the chosen face's baseline. Inter stays the default. San Francisco is drawn at the text optical size following @thisisgm's work in crmne/zapfast#279.
- **Colour emoji in the platform's own style, in a new crate, `fastframe-emoji`.** Apple Color Emoji on macOS, Segoe UI Emoji on Windows, and the desktop's colour emoji font on Linux, with a font the app bundles for anything the platform lacks (Windows has no country flags, for instance). Whole sequences (flags, skin tones, families) become one picture, as the platform joins them, placed where and as wide as the platform draws them. Each emoji is laid out as one placeholder glyph, so selecting, wrapping and copying work on it, and new pictures are drawn on a worker thread instead of stalling the frame that first shows them. `Emoji::render` hands a picture to renderers outside egui. The Windows renderer is @pulgueta's from crmne/zapfast#229, and joining Apple's sequences over a memory-mapped font is @thisisgm's from crmne/zapfast#279.
- **Tray entries can come and go while the app runs.** `Tray::set_visible(id, shown)` shows or hides an entry in its place, on Linux, Windows and macOS, and `MenuItem::action(..).visible(false)` starts one hidden. ZapFast uses it to offer "Lock ZapFast" as soon as an app lock password is set, instead of after a restart.
- **Apps that always use the system's face can leave Inter out.** Inter (880 KB) is now behind the `inter` feature of `fastframe-fonts`, on by default.

## Fixed

- **A tray label changed while the Windows tray menu is open is no longer lost.** The open menu swallowed the request to apply it, so the menu kept the old label (Spotifast's Play or Pause, say) until the next change. Changes now apply as the menu closes.

## Upgrading from 0.1.7

- **`fastframe_tray::MenuItem::Action` has a new field, `visible`.** Code that builds the variant with a struct literal must add `visible: true`, or use `MenuItem::action(id, label)`, which sets it. A pattern that names every field (`MenuItem::Action { id, label }`) needs `..`. Apps that only call `MenuItem::action` and compare with it (ZapFast, Spotifast) need no change.
- **`fastframe-fonts` bundles Inter only with its `inter` feature.** The feature is on by default. An app that depends on `fastframe-fonts` with `default-features = false` must add `features = ["inter"]` to keep Inter; without it, and without `Primary::System`, egui's own fonts draw the interface.
- **The system's interface face draws proportional figures.** San Francisco and Segoe UI draw proportional figures (egui does not apply their `tnum` feature), unlike the bundled Inter with its tabular figures frozen in, so an app that turns on `Primary::System` and shows a counting timer should draw that timer with Inter, or accept that its width changes as it counts.
- Adopting `fastframe-emoji` is optional; see the moving-apps guide for what ZapFast replaced with it.
